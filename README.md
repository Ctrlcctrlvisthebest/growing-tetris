# Growing Tetris

一个会在下落过程中不断生长的俄罗斯方块网页游戏。

**[直接开玩](https://ctrlcctrlvisthebest.github.io/growing-tetris/)** · [Cloudflare 备用入口](https://growing-tetris-leaderboard.zoeli2010xl.workers.dev) · [源码](https://github.com/Ctrlcctrlvisthebest/growing-tetris)

## 语言与两版同步

游戏支持中文和 English，开始页、游戏工具栏、成绩面板和按键设置均可切换。Toy 首次打开默认中文，GitHub Pages 和源码默认英文；玩家手动选择的语言优先，并保存在当前浏览器、当前域名。切换语言只刷新文案，不重开对局、不改变分数或生长计时，也不翻译玩家昵称。

两版必须共用同一套玩法、移动交互、增长计时和昵称审核代码；后续所有 Toy 功能更新也同步进入 GitHub 版。`i18n.js` 维护翻译，`locale-config.js` 提供默认语言，构建时分别生成 `en` 与 `zh-CN`。构建一致性测试保证核心资源完全相同，仅默认语言和平台附属文件不同。

推送 `main` 后现有 GitHub Actions 先运行回归测试，再通过 `npm run build` 同时生成英文默认的 `dist/` 和中文默认的 `dist-toy/`，然后发布 GitHub Pages。本机使用同一提交生成 Toy 包，预览后按平台流程提交审核；两个平台的正式发布时间可能因审核而不同。无需修改 GitHub 工作流或增加令牌权限。

## 操作

- `←` / `→`：移动
- `↑`：顺时针旋转
- `Z`：逆时针旋转
- `X`：旋转 180°
- `↓`：加速下落
- `Space`：直接落下
- `C`：存储或交换方块；每回合只能使用一次
- `F`：使用冻结道具，停止生长 8 秒
- `P`：暂停或继续游戏
- `H`：切换普通/困难模式并重新开局
- `R`：重新开始

点击页面右上角的 `KEY SETTINGS` 可以修改键位。点击一个动作后按下新键即可完成绑定；如果新键已被其他动作使用，两个动作会自动交换键位。设置保存在当前浏览器中，也可以使用 `RESET DEFAULTS` 恢复默认值。退出键用于取消本次按键捕获，修饰键、刷新键和开发者工具键不可绑定。

手机端点击 `START GAME`／`开始游戏` 开局。棋盘内左右滑动移动方块，上滑或轻点旋转，下滑至少 48 CSS 像素并松手后直接落下；较短的下滑不会落块。手势锁定主方向，多指、系统取消、切后台或方块已换新时取消手势。棋盘两侧、下方和弹窗保留页面滚动，按钮在松手点击后触发，滑动经过按钮不会直接开局或执行动作。底部按钮仍可使用。

游戏使用四首原创自然小调 8-bit 背景音乐。每次新开局固定从 A 自然小调的 `growing-tetris-a-natural-minor-fast.m4a` 开始；第一首结束后，它会与快速切分 A 小调版和重鼓 D 小调版共同随机轮换。E 小调高速街机版只在困难模式，或普通模式的实际生长间隔不高于 150 帧时加入候选池。连续两首不会重复；如果高速曲播放期间降低生长速度，系统会立即切回普通候选曲目。

页面右上角的 `MUSIC ON / OFF` 可以随时开关音乐，选择会保存在当前浏览器中。暂停游戏、打开按键设置、切换到后台或游戏结束时音乐也会暂停。

## 本地成绩记录

点击开始页的 `SCORE HISTORY` 或左下角的 `SCORES` 查看每局分数、日期、模式和结果，以及普通／困难模式的最高分。查看时暂停游戏和音乐，关闭后恢复原先状态。

每局开始时创建记录，方块落定后更新分数，游戏结束时结算；重新开始或切换模式会保留上一局。中途刷新或关闭页面后，最近保存的分数仍可查看，并标为 `Unfinished`（未完成），但不会恢复棋盘。每页显示 20 条，按新到旧排序，可以翻页查看全部记录，或用 `EXPORT CSV` 将全部成绩下载到本地。

完整历史记录写入浏览器 `localStorage`，不需要账号；此前的本地历史不会批量上传。新增全球排行榜后，新完成对局的昵称、分数和模式会单独提交到共享服务。每局使用独立存储项，避免多窗口相互覆盖，并且不会在每帧读取或重写历史记录。浏览器拒绝保存或空间不足时，成绩面板会提示，并暂时保留当前会话中的记录供导出。

成绩属于当前浏览器和访问地址；更换浏览器、域名或端口不会共用记录。清除网站数据会删除成绩，无痕窗口结束后数据也可能消失，重要成绩可导出备份。直接双击 `index.html` 时，本地存储是否可用取决于浏览器；建议固定使用同一个本地地址，例如 `http://127.0.0.1:8876/`（在项目目录运行 `python3 -m http.server 8876 --bind 127.0.0.1`）。

旋转采用标准 Super Rotation System（SRS）：七种方块使用标准出生姿态和旋转中心，I 方块与 J/L/S/T/Z 方块分别使用对应的官方踢墙表。O 方块原地旋转；180° 旋转按两次连续的 SRS 90° 旋转处理。

方块落地后有约 650ms 的锁定延迟。在锁定前仍可左右移动或旋转，成功操作会重新计算锁定时间；每个方块最多重置 15 次，硬降会立即锁定。

早期 Processing 版本保存在 `legacy/`；当前网页版本的入口为 `index.html`。

## 全球前三名

游戏前端托管在 [GitHub Pages](https://ctrlcctrlvisthebest.github.io/growing-tetris/)，排行榜接口和 D1 数据库运行在 Cloudflare。GitHub 页面和 Cloudflare 备用入口共用全球榜单；完整本地历史仍按访问地址分别保存。

在开始页填写公开昵称（可留空，默认为 `Player`）。打开 `SCORES` → `GLOBAL TOP 3` 可查看所有设备共同的前三条最高成绩，并按普通／困难模式筛选。分数从高到低排序，同分以服务端收到的时间为准；同一昵称可以占多个位置，昵称不是账号。

只有游戏自然结束的对局会提交；重开、切换模式和未完成对局仍保留在本地历史。昵称在开局时确定，成绩面板中的改名用于下一局。每局使用唯一 ID，网络重试不会重复上榜。断网时先保存待提交记录，重新联网、打开成绩面板或点击 `Refresh` 时重试。服务端确认成功或明确永久拒绝的记录会移出上传队列，完整本地历史继续保留；网络错误保留队列重试。清除网站数据也会删除尚未上传的队列。

自定义昵称通过 Cloudflare 的 `POST /api/nickname/check` 审核后用于新对局；输入中文时等待输入法组词完成再检查。命中规则时要求改名；审核服务不可用时可使用 `Player` 继续游玩。成绩提交接口会再次审核，不能绕过前端直接写入违规昵称；更新规则后，榜单上已存在的违规昵称显示为 `Player`，原成绩不会被删除。

审核使用 `server/nickname-policy.mjs` 中维护的基础词库，覆盖常见政治敏感名字、部分变体和不适合公开展示的词语，并处理繁简体、全半角、零宽字符、分隔符及部分同形字绕过。它不是 B 站官方审核服务，也不是穷尽词库。可在该文件扩充规则，或在 `wrangler.jsonc` 的 `NICKNAME_BLOCKLIST` 追加逗号／换行分隔的词条后重新部署；词库仅放在服务端，不打入 Toy 前端包。没有新增付费审核服务或数据库迁移。

共享服务使用 Cloudflare Workers + D1，只保存对局 ID、昵称、分数、模式和接收时间。查询通过索引获取前三条；页面首屏不请求排行榜，游戏运行过程中也不轮询。接口限制提交大小、字段和频率，并使用参数化 SQL。当前是休闲游戏排行榜，分数由客户端报告，没有账号认证或服务端回放校验，不适合有奖竞赛。

与 Before the Rain Stops 一样，GitHub Pages 是正式游戏入口，Cloudflare 提供后端和备用入口。

- `npm run build` 默认生成生产前端，保留 `leaderboard-config.js` 中公开的 Cloudflare API 地址。JS、CSS 和音频使用相对路径，兼容 `/growing-tetris/` 仓库子路径。
- `wrangler.jsonc` 中的 `ALLOWED_ORIGINS` 已允许 `https://ctrlcctrlvisthebest.github.io` 和本地 8876 端口。更换前端域名时，更新允许来源并重新发布后端。

后端代码更新后，在本机发布排行榜服务及备用入口：

```sh

```

该命令构建静态资源、迁移远端数据库并发布 Worker；`npm run deploy` 是同一命令的别名。`wrangler.jsonc` 继续绑定原有的 `growing-tetris-leaderboard` 数据库，已有全球成绩保留。部署凭证由本机 Wrangler 管理。更换 Cloudflare 账号时，先创建自己的 D1 数据库并替换 `database_id`，同时修改前端 API 地址。

## 代码如何工作

`index.html` 提供画布容器和控制按钮，`style.css` 负责桌面与触屏布局，`sketch.js` 保存游戏规则和帧调度，`renderer.js` 提供轻量原生 Canvas 2D 绘制函数，`score-history.js` 负责本地历史与 CSV 导出，`leaderboard.js` 负责全球排行榜、昵称与待提交队列，`server/worker.mjs` 提供共享成绩 API，`assets/audio/` 保存背景音乐。游戏资源均在项目内，不依赖外部脚本 CDN；单机玩法可直接静态运行，共享排行榜需要后端。

页面解析完成后调用 `setup()`：创建逻辑尺寸为 500×700 的画布、缓存 DOM 控件、绑定键盘和触屏事件，然后调用 `restartGame()` 创建棋盘、预览队列和第一个活动方块。`requestAnimationFrame` 将游戏更新限制为每秒最多 60 次，120/144 Hz 屏幕不会加快生长。`draw()` 先更新输入、生长、自动下落和锁定计时，再绘制棋盘、落点提示、活动方块和界面。开始页、暂停、按键设置和结束后的静态画面只绘制一次；切到后台停止更新，恢复时不会补算后台经过的时间。

棋盘图像只在锁定方块或消行后重建，落点计算按棋盘版本、位置和形状缓存。画布像素密度最高为 2，兼顾清晰度与高分屏绘制成本；CSS 提前预留画布空间，避免加载时布局跳动。冻结按钮只在显示文字或可用状态变化时写入 DOM。

音乐使用 64 kbps 单声道 AAC/M4A，每首约 184–216 KiB，比原始 WAV 小约 82%。开始页设置 `preload="none"`，只有开始游戏并启用音乐后才下载当前曲目。原始 WAV 保留用于后续编辑。macOS 可用以下命令重新生成压缩音频：

```sh
for audio_source in assets/audio/*.wav; do
  afconvert "$audio_source" "${audio_source%.wav}.m4a" -f m4af -d aac -b 64000 -q 127
done
```

`Board` 保存已经落地的方格。活动方块移动或旋转前通过 `Board.isValid()` 检查边界和碰撞；落地后由 `Board.lock()` 写入网格，再由 `Board.clearLines()` 删除填满的行。`Piece` 保存当前形状的局部坐标、棋盘位置、颜色、旋转状态和生长提示。旋转通过标准 SRS 旋转中心及踢墙表寻找第一个合法位置。

普通模式用真实毫秒累计生长周期，速度公式仍沿用原来的 60 Hz 基准并换算成时间；预警提前 750ms，周期结束后把警告格加入形状，跨周期的余量保留。10–144 Hz 和抖动帧率下增长周期相同；单次异常卡顿最多推进 100ms，暂停和后台时间不补算，避免恢复后突然连续生长。默认滑杆 3 档时，17 级为 1.1 秒一次，18 级及以上达到原有的 1 秒下限；99 级不会再因 30 Hz 变成约 2 秒一次。冻结结束当帧剩余的未冻结时间继续计入生长。困难模式不使用普通计时，而由 `performOperation()` 统计有效玩家操作：第一次有效操作显示警告，第四次有效操作提交生长。失败移动、失败旋转和不可用 Hold 不增加计数。

方向键长按时，第一次按下计作一次困难模式操作；之后自动重复产生的连续移动或软降不重复计数。

自动下落使用毫秒计时。方块接触地面后开始约 650ms 的锁定延迟；成功横移或旋转可以重置延迟，但每个方块最多 15 次。硬降跳过延迟并立即调用 `lockAndSpawn()`。Hold 保存的是形状快照，交换回来时会重新计算出生位置，避免生长后的大形状错误复用旧坐标。

全局可变变量表示当前单局状态，例如分数、模式、计时器、活动方块和道具数量。修改规则时应优先经过 `performOperation()`、`lockAndSpawn()` 和 `restartGame()` 这三个统一入口，避免键盘、触屏和自动流程产生不同结果。

## 测试

运行 `npm test` 可以执行游戏规则和回归测试，覆盖多行消除、异常形状、顶部越界锁定、困难模式计数、异常回滚、长按输入、自定义键位、键位冲突、损坏存储回退、音乐配置、冻结计时、锁定延迟上限、缓存失效、空闲停止绘制、60/120/144 Hz 调度一致性，以及成绩去重、重开／模式切换、刷新与多窗口保存、存储异常和成绩面板输入隔离。全球排行榜测试覆盖跨会话排序、同分和模式筛选、重复提交、输入校验、跨域与限流、断网队列和旧历史不上传；API 测试用内存 SQLite 执行真实迁移和查询。触屏与昵称回归覆盖上下滑阈值、横滑操作计数、取消／多指／换块保护、滑动不激活按钮、昵称异步响应顺序、违规与正常昵称、接口直接提交拦截、自定义词库和历史昵称隐藏。真实手机上的浏览器手势与系统中断行为仍需设备验收。

棋盘中的灰色粗边框会显示当前方块垂直下落后的最终位置，并会随移动、旋转和生长实时更新。

消行后，棋盘左侧会显示本次消除名称和得分并上浮淡出：单消 100 分、双消 400 分、三消 900 分、四消（TETRIS）1600 分。

困难模式中，第一次操作显示下一次生长位置，第四次操作让该位置生长；之后每四次操作重复这一循环。

普通模式可以使用棋盘左侧 Freeze 下方的拉杆调整生长速度。游戏每锁定 5 个方块提升一个速度等级，每级只小幅提速，并在棋盘右侧显示 `SPEED UP!`。困难模式由操作次数控制生长，因此拉杆和自动提速不生效。

勾选 `Directed growth` 后，方块固定横向向右生长。闪烁期间旋转方块，提示会重新出现在旋转后结构的右侧，可以借此控制下一次生长的位置。

每消除一行会获得 1 个冻结道具；多行同时消除会获得多个。冻结期间普通模式和困难模式都不会生长。


### Toy JSSDK 排行榜

Toy 构建通过 `platform-config.js` 选择官方 JSSDK 排行榜，并按官方地址动态加载 `window.toy`；GitHub 构建仍使用原 Cloudflare API。其他后端连接和数据库保持不变。

- 普通模式使用榜位 1，困难模式使用榜位 2；总榜/月榜/周榜/日榜分别读取对应周期。
- 公开榜单调用 `getRankList`，点击“我的排名”调用 `getMyRank`；是否上榜以 `ranked` 为准。
- 游戏结束后在成绩页点击“提交已完成成绩”，调用 `submitScore` 提交绝对分数；平台完成用户确认并保留个人最高分。Toy 昵称由 B 站账号提供。
- 仅保留本次页面会话、各模式最近完成的一局供提交，刷新页面后仍保留本地历史，但不自动补交历史成绩。不导入原 Cloudflare 上传队列，以免把旧成绩归到另一账号或新的统计周期。
- 超出 Toy 分数范围时不截断或伪造分数，只保留本地历史。登录失败、取消确认、网络失败可手动重试。
- 平台榜单只能在支持的 Toy 容器中联调；localhost、GitHub 和 Cloudflare 备用预览不具备 Toy 宿主环境。
